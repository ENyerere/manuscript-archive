## 为什么要自己的服务器

GitHub Pages 用得好好的,为什么要折腾?三个理由:国内访问 Pages 一直不算稳定;
备案后的国内服务器对搜索引擎更友好;以及——说实话——想完整走一遍
「买机器、配环境、绑域名、挂证书」的流程,这些知识只看教程是学不会的。

## 服务器与 Caddy

最后选了阿里云的一台入门 ECS,2 核 2G,跑一个静态博客绰绰有余——它甚至还在兼职
跑一个 Minecraft 多人服,域名解析过去之后,朋友们直接用 `yshenyi.ink` 就能进游戏,
比报一串 IP 体面多了。

Web 服务器没用 Nginx,选了 Caddy。理由很朴素:配置短。整个站点的配置核心就是
几行——指定根目录、开压缩、SPA 回退,完事。HTTPS 证书是 Caddy 自动申请和续期的,
Let's Encrypt 全程无感,不用记 crontab,不用操心过期。

## 备案:一段等待的时间

买域名很快,起名想了很久,最后定了 `yshenyi.ink`——「峄」配上「墨」,
和手稿档案的气质刚好合上。但 `.ink` 在国内要正常访问,得先过 ICP 备案。

流程比想象中顺利:在阿里云 App 上拍照、填表、刷脸,提交后就是等。管局审核
大约两周,通过那天收到短信,拿到备案号,立刻挂到了页脚——
页脚那块墨色反转的区域,现在多了一行小字,链到工信部备案系统。
从「能访问」到「合法地能访问」,差的就是这一行字。

## 部署管线:写作依然是提交

服务器换了,写作流程没变,甚至更顺了:

1. 在 `src/content/posts/` 里新建一个 `.md` 文件
2. `git commit`,`git push`
3. GitHub Actions 构建产物,rsync 同步到服务器的 `/var/www/blog`
4. Caddy 直接服务静态文件,全程几十秒

和 Pages 时代唯一的区别:终点的机器是自己的。DNS、证书、回退规则都在
一份几 KB 的 Caddyfile 里,整个站点的基础设施可以被完整复述——这种
「没有黑盒」的感觉很好。

## 顺手做的:构建期渲染

部署稳定之后,又做了一次比较大的重构:Markdown 不再由浏览器里的
`react-markdown` 实时解析,而是在构建时直接转成 HTML。每篇文章、每个标签页
都会预生成一份独立的静态页面,带自己的标题、描述和 OG 信息;
`<noscript>` 里放着正文,不执行 JS 的爬虫也能读到完整内容。

附带的收益很可观:文章页的 JS 从 344KB 瘦到 8.5KB,字体从 66 个文件减到 4 个,
RSS 也从摘要升级成了全文输出。读者侧无感,机器侧天差地别。

## 卷末
